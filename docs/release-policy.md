# Edge Office 发布策略

## 目标

将网页、Windows 桌面 App 和手机 App 从“每次改动都同步发布”改为按影响范围分层发布，减少重复打包、测试和分发成本。

## 三档发布规则

| 改动级别 | 典型改动 | 默认平台 | 版本建议 |
| --- | --- | --- | --- |
| 小改动 | 文案、样式、交互细节、非破坏性网页修复、文档 | 网页 | `web-YYYYMMDD` 或补丁版本 |
| 较大改动 | RAG、Agent、模型适配、后端 API、PPT 工作区、安装包和运行时变化 | Windows 桌面 App | `v0.x.y` |
| 重大版本 | 破坏性 API、核心架构、权限/安全策略、移动端体验重构、模型协议变化 | 手机 App；必要时同步 Windows/网页 | `v1.0.0` 或主版本升级 |

## 判定原则

1. 只影响网页展示和非破坏性逻辑的改动，不触发桌面或手机打包。
2. 影响本地模型、RAG、Agent、PPT 执行器、数据库或安装运行时的改动，优先进入 Windows 桌面发布线。
3. 只有会改变用户核心工作流、移动端架构或兼容性边界的改动，才进入手机 App 主版本。
4. 安全、数据丢失和严重回归问题属于热修复，可直接发布到受影响的平台，不等待完整三端同步。
5. “源码已修改”“本地可运行”“已构建安装包”和“已公开发布”是四种不同状态，版本台账必须分开记录。

## 每次发布的最小记录

- 版本号或开发标识、日期、变更摘要。
- 目标平台和平台状态：已发布、本地可用、工程已加入、未发布或计划。
- Git commit、Release URL、构建产物或测试结果等证据。
- 回滚方式和下一步动作。
